# 시장충격 테스트 - 대형 플랫폼 진입 시나리오

가정: 네이버지도·카카오 같은 대형 플랫폼이 "친구와 후보를 모아 같이 고르기" 기능을 출시한다면, 뭐할까에는 가장 현실적인 충격 테스트가 된다.

## 1. 가장 먼저 무너지는 가정

"함께 결정하는 기능 자체가 차별점이다"라는 가정이 가장 먼저 무너진다. 대형 플랫폼이 후보 공유·투표를 제공하면 사용자는 굳이 뭐할까로 이동할 이유가 줄어든다. 따라서 뭐할까의 가치는 '투표' → '같은 사람들과의 과거 선택을 기억해 다음 결정을 쉽게 만드는 것'으로 더 강하게 이동해야 한다.

## 2. 사업에 미치는 영향

| 항목 | 영향 |
|---|---|
| 매출 | 광고 노출·예약 연결 감소 가능. 사용자가 네이버/카카오 안에서 결정을 끝내면 수익 기회가 줄어듦 |
| 고객 | 신규 사용자 확보가 어려워짐. "이미 지도에서 되는데?"가 가장 큰 이탈 이유가 됨 |
| 비용 | 광고 CAC 상승 가능. 기존 플랫폼과 기능 경쟁을 하면 개발비도 커짐 |
| 차별화 | 단순 후보 모으기·투표는 약해짐. 관계별 기억·반복 결정 데이터가 핵심으로 남음 |

## 3. 무엇을 바꿀 것인가

- **타겟**: 크게 바꾸지 않음 → 같은 사람들과 반복적으로 결정하는 2~4명 관계에 더 집중
- **제품**: 가장 크게 변경 → 단순 투표보다 "지난번 너희가 뭐 골랐는지 → 이번에는 어디가 맞는지"를 보여주는 관계 기억 강화
- **가격**: 초기에는 무료 유지 → 경쟁 플랫폼이 무료인데 사용자에게 바로 과금하면 더 불리함
- **채널**: 광고 의존도를 낮춤 → 한 명이 링크를 보내고 다른 사람이 참여하는 초대 기반 확산을 핵심 채널로
- **수익모델**: 광고만 의존하지 않음 → 스폰서십 + 예약 제휴 + 향후 프리미엄 관계 기능으로 분산

## 4. 10분 발표용 정리

1. **충격 상황(1분)**: "네이버지도나 카카오가 친구들과 후보를 공유하고 투표하는 기능을 출시했다고 가정했습니다."
2. **무엇이 무너지나(2분)**: "그러면 뭐할까의 '후보를 모아 같이 고른다'는 기능 자체는 더 이상 차별점이 아닙니다."
3. **사업 영향(2분)**: "신규 고객 확보는 어려워지고 CAC는 높아질 수 있으며, 광고·예약 매출도 플랫폼 내부에서 흡수될 가능성이 있습니다."
4. **어떻게 대응하나(3분)**: "대형 플랫폼이 잘하는 '장소 찾기'를 따라가지 않고, 같은 사람들과 반복해서 결정할수록 더 편해지는 관계 기억에 집중합니다."
5. **최종 결론(2분)**: 시장충격 이후 뭐할까의 전략은 '같이 투표하는 앱'이 아니라 '이 사람들과 다음 결정을 더 쉽게 해주는 앱'으로 좁히는 것이다. 대형 플랫폼과 검색·지도에서 경쟁하지 않고, 반복 관계와 결정 기억에서 차별화한다.

**한 줄 압축**: 충격 전 - 찾은 후보를 같이 결정. 충격 후 - 같은 사람들과의 과거 선택을 기억해 다음 결정을 더 쉽게.

## 담당 배분

| 항목 | 1차 담당 | 이유 |
|---|---|---|
| 시장충격 시나리오 설계·경쟁 위협 분석 | Researcher | "아직 검증되지 않은 가정을 구현으로 굳혀버렸는가?" - 지금은 대형 플랫폼이 실제로 이 기능을 출시한 게 아니라 가정 시나리오다. 이 시나리오 자체와 여기서 나온 결론(관계 기억이 핵심 차별화)도 계속 가설로 취급하고 실측 전까지 확정하지 않는다. |
| 전략 피벗(투표 앱 → 관계 기억 앱) 최종 승인 | CEO | 타겟·가격·채널·수익모델 전반에 걸친 변경이라 범위 승인이 필요하다. "제품 범위를 벗어난 기능이 들어갔는가?"가 아니라 "지금 범위를 좁히는 결정"이므로 CEO가 검토·승인한다. |
| 제품 변경(관계 기억 강화, 단순 투표 비중 축소) | PM | "지난번 너희가 뭐 골랐는지 → 이번에는 어디가 맞는지"를 보여주는 게 흐름 어디에 들어가야 가장 짧은지 PM이 설계한다. |
| 포지셔닝 전환("같이 투표하는 앱" → "다음 결정을 더 쉽게 해주는 앱") | Brand Manager | 기존 판단 기준("Discover/Save 앱처럼 보이지 않고 Decision 앱으로 보이는가?")과 같은 결의 판단 - 이번엔 "투표 앱처럼 보이지 않고 관계 기억 앱으로 보이는가"로 확장해서 본다. |
| 채널 전환(광고 의존도 축소, 초대 기반 확산 강화) | Marketer/Creator | CAC가 오를 수 있는 상황에서 유료 획득 대신 초대 확산을 핵심 채널로 미는 결정이라 Marketer/Creator가 실행을 책임진다. |
| 관계 기억이 실제 차별화인지 측정 | Data Analyst | 이 전략 전체가 Same-pair Repeat(같은 관계가 다시 쓰는가)가 실제로 오르는지에 달려 있다 - 이미 확정한 Churn 지표(`agents/data-analyst.md`)와 같은 지표로 검증한다. |

전체 지표 배분 원칙은 `agents/BUSINESS_METRICS_OWNERSHIP.md`, 수익모델은 `agents/REVENUE_MODEL.md` 참조.
