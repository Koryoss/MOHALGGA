# 뭐할까 수익모델 제시안 - 담당 Agent 배분

수익모델 자체는 어느 한 역할의 전문 영역이 아니라, 전략 승인(CEO) · 가정 검증(Researcher) · 신뢰 리스크(Brand Manager, CS) · 현재 범위 확인(PM)이 겹치는 영역이라 하나로 모아 정리하고, 각 역할 파일에는 자기 몫만 짧게 얹는다.

## 1. 스폰서십 광고 - 1순위

- 페이어: 식당·카페·전시·액티비티 사업자
- 수익 방식: 스폰서 장소 노출, 지역/상황 맞춤 프로모션
- 가격: 월 300만 원/광고주 가정
- 10억 달성 예시: 광고주 20곳 × 월 300만 원 × 10개월 = 6억 원
- 장점: 사용자는 무료로 유지하면서 결정 순간을 수익화 가능
- 리스크: 광고가 추천·투표 결과를 왜곡하면 신뢰 하락

## 2. 예약·액티비티 제휴 - 2순위

- 페이어: 예약 플랫폼·식당·액티비티 사업자
- 수익 방식: 뭐할까를 통해 예약·구매 발생 시 수수료
- 가격: 거래액의 8% 제휴수수료 벤치마크
- 10억 달성 예시: 전체 목표 중 4억 원 담당 시 → 연 예약 거래액 50억 원. 평균 결제 10만 원 가정 시 → 연 5만 건 예약
- 장점: 실제 결정이 구매로 이어질 때만 수익 발생
- 리스크: 결정은 많이 일어나도 예약 전환이 낮을 수 있음

## 3. 프리미엄 구독 - 보조 모델

- 페이어: 반복 사용이 많은 개인·모임 주최자
- 수익 방식: 관계별 기억 고도화, 과거 선택 활용, 거리·상황 반영 등
- 가격: 아직 검증 필요
- 장점: 광고와 무관하게 반복 사용자 자체에서 매출 발생
- 리스크: 카톡·지도 등 무료 대안이 강해 지불의사가 낮을 수 있음

## 4. 향후 B2B / 데이터·API - 장기 확장

- 페이어: 예약·로컬·여가 플랫폼 또는 기업
- 수익 방식: 그룹 선택·취향 데이터 기반 API, 제휴 솔루션
- 가격: 향후 계약 기반
- 장점: 소비자 서비스에서 축적된 관계·결정 데이터를 사업자로 확장 가능
- 리스크: 충분한 사용자 데이터가 쌓이기 전에는 가치가 없음

## 추천 구조

무료 사용 → 함께 결정 → 스폰서십 노출 → 예약·구매 → 제휴 수수료. 여기에 반복 사용이 충분히 확인되면 프리미엄 구독, 장기적으로는 B2B/API를 추가하는 구조.

## 사업계획서용 요약

- 선택모델: 스폰서십 광고 + 예약 제휴 / 향후 Premium·B2B 확장
- 가격: 스폰서 월 300만 원 가정 / 예약 거래액 8% 제휴수수료 벤치마크
- 10억 달성 예시: 스폰서십 6억 + 예약 제휴 4억
- 선택 이유: 사용자는 무료로 유지하면서 결정 과정과 결정 이후의 구매 행동을 모두 수익화할 수 있다.
- 단서: 월 300만 원·평균 결제 10만 원은 아직 가정이고, 8%도 국내 뭐할까의 확정 계약률이 아니라 외부 제휴 벤치마크다. 실제 사업성은 광고주 지불의사와 예약 전환율을 먼저 검증해야 한다.

## 담당 배분

| 항목 | 1차 담당 | 이유 |
|---|---|---|
| 수익모델 채택·타이밍 최종 승인 | CEO | 재무 전담 역할이 없어 Margin과 동일하게 CEO가 흡수. "지금 이 범위가 맞는가"를 최종 판단. |
| 가격·수수료 가정 검증(월 300만 원, 8%, 평균결제 10만 원) | Researcher | "아직 검증되지 않은 가정을 구현으로 굳혀버렸는가?" 기준 그대로. 지금은 전부 가정이며 광고주 지불의사·예약 전환율 실측 전까지 사실처럼 쓰지 않는다. |
| 스폰서십이 추천/결정을 왜곡할 위험 | Brand Manager + CS | Brand Manager: "Discover/Save 앱처럼 보이지 않고 Decision 앱으로 보이는가?" - 스폰서 노출이 눈에 띄게 섞이면 브랜드 약속과 충돌. CS: "앱은 평가자가 아니라 결정을 돕는 보조자" - 스폰서 후보가 스와이프 순서·노출을 왜곡하면 신뢰 붕괴로 이어진다. |
| 현재 단계 범위 확인 | PM | 수익모델은 지금 P0(URL → Candidate → Reaction → Decision 흐름 완성)에 포함되지 않는다. 스폰서 후보가 지금 흐름에 섞이지 않도록 지킨다. |
| 예약 전환·구독 전환 측정(향후) | Data Analyst | 지금은 결제 자체가 없어 측정할 수 없다. Conversion/Churn이 먼저 증명된 다음 예약 전환율 계측을 설계한다(`agents/data-analyst.md` 참조). |

전체 지표 배분 원칙은 `agents/BUSINESS_METRICS_OWNERSHIP.md`, Conversion/Churn 확정 지표는 `agents/data-analyst.md` 참조.
